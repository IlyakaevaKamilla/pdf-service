# pdf-service (gateway)

**Роль**: Легкий шлюз, принимает заявки, управляет SSE-соединениями и отдает готовые PDF из БД.

## Авторизация
Используется мидлварь `internal_middleware`. Все ручки, кроме вебхука, требуют заголовок `X-User-ID` или `X-User-Claims`.

## Эндпоинты
`POST /api/pdf/generate_tour` — приём заявки на генерацию. Принимает JSON с `request_id`, `template_id` и `payload`. Очищает пользовательские строки, валидирует структуру и отправляет задачу в Kafka.

`GET /api/pdf/events/{request_id}` — SSE-поток. Фронт открывает его сразу после нажатия кнопки и ждет результата. Шлюз держит соединение, пока не придет вебхук от воркера.

`POST /api/pdf/internal/pdf-ready` — вебхук. Сюда стучится Воркер ([2 сервис](https://github.com/IlyakaevaKamilla/pdf-generator.git)) после завершения генерации. Шлюз находит SSE-соединение по `request_id` и отправляет фронту данные (`status`, `url`).

`GET /api/pdf/download/{request_id}` — скачивание файла. Шлюз достает `file_data` из БД и отдает пользователю.

`GET /api/pdf/history` — история генераций текущего пользователя (с фильтрацией по городам, датам, активности).

## Поток работы
1. Фронт отправляет POST-запрос с JSON и сразу открывает SSE.
2. Шлюз валидирует, чистит данные и кладет в Kafka.
3. Ждет вебхук от воркера.
4. Получает вебхук, отправляет данные в SSE.
5. По ЭП /download отдает файл из БД.
